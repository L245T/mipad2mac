# 实机协议记录 · 2026-09-16

来源：本机 IORegistry 中已连接 Xiaomi Pad 9 Pro Max 的 HID Report Descriptor。只保存产品通用描述符，不保存序列号、系统账户名或完整注册表。

VID `0x2717` / PID `0x2d05`。本次 USB 配置包含一个 class 6/subclass 1/protocol 1 接口、键盘/鼠标 HID、数位笔 HID（class 6 接口实际用途尚未确认）。视频连接不由本工具接管。`system_profiler` 在执行环境内未显示完整 USB/显示信息；本结论依据 `hidutil` 与 `ioreg`，不据此判定显示输出状态。

## 数位笔

顶层 Usage Page `0x0d` / Usage `0x02`（Pen），子集合 Stylus `0x20`。

| 字节（含 Report ID） | 内容 | 来源 |
|---|---|---|
| 0 | Report ID = 3 | `85 03` |
| 1 bit 0 | Tip Switch | `09 42` |
| 1 bit 1 | Barrel Switch | `09 44` |
| 1 bit 2 | Eraser | `09 45` |
| 1 bit 3 | In Range | `09 32` |
| 1 bit 4–7 | 常量填充 | `75 04 81 03` |
| 2–3 | X，16 位小端，0…32767 | Generic Desktop X |
| 4–5 | Y，16 位小端，0…32767 | Generic Desktop Y |
| 6–7 | 压感，16 位小端，0…8191 | Tip Pressure |
| 8 | X Tilt，有符号 8 位，-60…60 | `09 3d` |
| 9 | Y Tilt，有符号 8 位，-60…60 | `09 3e` |

当前没有 Finger 集合，没有 Contact ID / Count，也没有声明用于切换触摸模式的 Feature Report。不能由此推断其他 DP-in 模式或固件不支持触控。需要比较手指与笔在当前模式下的实际报文，再考虑 Windows 对照。

## 键盘/鼠标

另一个 HID 接口：Report 1 为键盘，Report 2 为鼠标（三按钮、16 位相对 X/Y、8 位滚轮）。v0.1.0 不打开此接口。v0.1.1 提供 15 秒限时诊断，仅订阅 Report 2 的鼠标元素，不读取键盘元素或注入鼠标事件。

## 运行验证

应用正常打开数位笔接口，已观察到 1,915 条报文全部解析成功。当时辅助功能和输入监控均未授权，鼠标控制关闭。示例真实报文：`03 09 8d 38 38 4f db 02 eb 1c`，对应 X=14477、Y=20280、接触且在范围内、压感=731、倾斜=(-21,28)。用户后续已确认这些数据全部来自笔，手指无反应。

## 下一步验证

1. `.app` 中检查接口已打开，完成必要的系统权限。
2. 手指按下、滑动、抬起，观察报文计数；如有笔，单独测试笔。
3. 若只有笔有数据，检查 DP-in 触控设置，并在 Windows 查看手指工作时的 VID/PID 和描述符是否不同。
4. 若描述符变化，保存新的匿名描述符，再新增对应解析器及独立测试。
5. 若需 Windows 初始化，先记录其控制传输；不向设备试写猜测的 Feature Report。

## v0.1.1 修订及验收边界

用户反馈：鼠标先在其他屏幕时不跳到平板；轻点不是单击；手指无反应。应用状态曾显示辅助功能未授权/控制未启用，但用户重新测试后报告问题仍在，不能将问题仅归因于权限。

修订包括：启用时独占已知笔接口；事件使用私有状态并在全局坐标显式定位；抬起沿用最后接触位置（观察到过 `03 08 00 00 ff 7f 00 00 00 00` 的无接触报文）；4 点以内抖动不变成拖动；新建 HID manager 处理重新连接；显示控制状态和已发送 down/up 数量。10 项自动测试通过。实际跨屏定位、单击及独占释放仍需最终构建的实机复测。

## 后续证据与边界

- 用户确认 Windows 下手指与笔均可直接控制电脑。Mac 侧仍无 Touch Screen 集合，鼠标通路 15 秒检测得到 0 次字段变化。该结果未覆盖 Windows 初始化或私有 USB 通路。
- 当前版本重开后可读取窗口。一次窗口无响应期间的 2 秒线程采样显示主线程主要在事件循环等待，没有证据证明 HID 调用死锁。未观察到 UPDD 后台进程，不能将安装痕迹当作输入冲突结论。
- 已在 v0.1.1 窗口确认“控制已启用、已独占笔接口”，后续计数为按下 8 / 抬起 8。这证明解析和提交链路工作，不证明事件已被目标应用接收或坐标准确。
- v0.1.2 使用事件源标签与测试窗口分别统计桥接/原生事件，补上端到端验收证据。Windows 采集脚本尚未在 Windows 运行。

用户进一步确认：选择文字或操作窗口时，笔操作阻塞，触控板单击后集中执行。旧 HID 回调和统计定时器只调度在 default run-loop mode，AppKit 的文字选择/拖动跟踪期间可暂停处理，导致虚拟 mouseUp 无法及时产生。v0.1.2 改用 common modes，需以文字选择和窗口拖动复测。跨屏问题仍由用户报告存在，尚未确认具体偏移，测试页与目标/当前光标坐标用于继续定位。
